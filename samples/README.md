# 国服真实海图样本

`charted.zh-CN.txt` 由玩家从国服客户端原样复制并提供。包含两张已测绘稀有海图；空格、标点、数值范围、属性分段及出售提示均保留。

## 验收预期

| 字段 | 样本 1 | 样本 2 |
| --- | --- | --- |
| 名称（两行合并） | 航海 冒险 珊瑚暗礁海图 | 航海 深入 金沙海床海图 |
| 目的地 | 蛤蜊海架 | 深渊平原 |
| 区域标识 | `clam-infested-shelf` | `abyssal-plain` |
| 区域等级 | 83 | 83 |
| 物品等级（原文） | 83 | 83 |
| 形状 | 端点 → `End` | 直线 → `Straight` |
| 连接（旋转前标准表示，北东南西） | `[true,false,false,false]` | `[true,false,true,false]` |
| 物品数量 | 110% | 110% |
| 亡者硫磺（头部总值） | 75% | 60% |
| 怪物群大小（头部总值） | 未列出 | 5% |
| 基底属性 | 相邻区域包含 8(8-10) 个额外的螃蟹群 — 数值不可调整 | 所有航行区域的怪物群规模提高 5% |
| 作用范围 | 相邻区域 | 整个航程 |

第一张基底属性语义对应 `adj-crab-1`，第二张对应 `voy-pack-1`；两者均已存在于英文数据表，保留其效果和评分参数，仅补国服文本映射。

显式属性区第一张的硫磺 +45% 与 +30% 已计入头部 +75%；第二张两条 +30% 已计入头部 +60%。解析时不能把正文再叠加到头部总值。

第二张头部怪物群大小 +5% 与基底的全航程群规模 +5% 是不同作用范围，应按原版模型分别表示；不能因为数值相同就合并或误当成重复正文。

## BDD 场景

- Given 空库存，When 导入样本 1，Then 加入一张 End 海图，并得到表中的名称、区域等级、目的地、奖励和相邻螃蟹词缀。
- Given 空库存，When 导入样本 2，Then 加入一张 Straight 海图，并分别识别头部奖励与全航程词缀。
- Given 空库存，When 一次导入整个文件，Then 加入两张不同实例的海图，不将两块文本合并成一个物品。
- Given 相同样本使用 Windows 换行，When 导入，Then 与原样本结果一致。
- Given 样本包含高级描述范围、不可调整后缀和出售提示，When 导入，Then 这些内容不破坏形状、名字或基底词缀匹配，不改变原版评分参数。
- Given 仍未识别的物品，When 导入，Then 使用现有失败提示，不新增待确认列表。
- Given 可识别形状但国服关键航行词缀无法匹配的派生样本，When 导入，Then 整张拒绝，不允许词缀效果缺失的海图静默进入库存；这是用户已确认的国服适配规则。

## 原版失败基线

2026-10-14，在英文线上网站将两份完整原文一同放入 Import 后点击 Parse & Add，显示 `skipped 1 unrecognised`，库存仍为 17（走查演示库存）。没有导入成功。

源码 `DIALECTS` 与 `ITEM_START_RE` 仅注册英文/韩文物品头，导致中文整块文本既没有按两张物品拆分，也没有被识别为海图。

同日台服网站实测：两张合并及分别导入均失败，库存保持0，提示 `已加入 0 張，跳過 1 項（不是海圖物品）`。合并导入也只计为一项。

## 覆盖限制

两张样本可以建立最小回归验收，但不能证明全部国服海图已支持。
追加真实文件 [charted-extra-shapes.zh-CN.txt](charted-extra-shapes.zh-CN.txt)
已校准角落、节点、交叉三种形状，与本文件合计五张，原两张全文不变。
追加来源、完整字段oracle与执行证据见 [client-shapes.md](../docs/acceptance/client-shapes.md)。
其他目的地与基底词缀、未测绘海图和边界词缀仍需继续采集，不以推测文案伪造真实样本。
