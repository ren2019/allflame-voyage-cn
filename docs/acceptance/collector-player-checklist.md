## R2 / R3 的可恢复操作

只在已认可的测试安装中执行，先 F7导出并从托盘退出。通过维护入口“查看版本与诊断”取得实际安装根和当前版本目录，再用文件资源管理器操作；不从旧版本截图猜路径。验收备份目录放在安装根之外。若菜单、文件名或候选与下文不一致，保留现象并反馈，不自行猜测。

- **真实旧→新**：交付报告应提供真实旧包和最终包的各自版本/摘要。先安装旧包，再由维护入口选择最终正常 ZIP，核对当前/目标及启动后版本。旧包只用于此行，其他行使用最终包。
- **网络失败**：先把安装根 `component-cache/colorama-0.4.6-py2.py3-none-any.whl` 移到验收备份，保留当前运行目录；断网后选择最终 starter 更新。应提示下载阶段失败，旧运行版本保持可用。恢复网络后重试，或把缓存归还。这个操作只是受控网络故障，不是新 OCR 效果样本。
- **摘要拒绝**：只选择交付中明确标记“派生校验失败输入、应拒绝执行”的独立 ZIP。它保留原清单而改坏 payload，仅用于验证执行前拒绝；不能当正常安装包、现场截图或最终候选。看见校验失败后核对旧版仍可启动。
- **切换失败**：维护者交付的已核对步骤是：退出后，给安装根稳定启动脚本 `launch-voyage-clip-collector-cn.ps1` 勾选“只读”，再尝试更新，记录是否实际触发替换失败及旧版回退。之后取消“只读”。不同 Windows 文件行为若未触发该故障，填“切换失败未测”，不得把更新成功写成失败回退通过；不修改系统权限来强行制造故障。
- **缺模型修复**：把维护入口显示的当前版本目录内 `runtime/python/Lib/site-packages/rapidocr_onnxruntime/models/ch_PP-OCRv4_det_infer.onnx` 移到验收备份，不删除。启动应拒绝；退出后从维护入口修复。修复失败可先将原文件归还再重试，不能把文件存在当作模型已能运行。

正常最终 ZIP、真实旧版本、派生校验拒绝输入必须分目录、分名称、分摘要交付。未收到明确材料时对应子项写缺证据；不让玩家自行改 ZIP、编造版本、编辑清单或输入额外命令。
