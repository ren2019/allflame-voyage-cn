# 永火航程规划 · 国服简体版

面向《流放之路》3.29 永火航程的海图库存与九宫格摆盘工具，支持国服海图导入、策略求解和跑图目标提示。

本项目基于 **[one-more-map 的 Allflame Voyage Solver](https://github.com/one-more-map/one-more-map.github.io)** 开发，是独立维护的国服适配 fork。原版的规划板、求解器与策略框架由原作者及贡献者提供；本仓库在此基础上增加简体中文、国服文本解析和下述规划辅助功能。感谢原作者开源。

[原版英文工具](https://one-more-map.github.io/allflame-voyage-solver/) · [使用与部署](docs/README.md) · [反馈问题](https://github.com/ren2019/allflame-voyage-cn/issues) · [参与贡献](CONTRIBUTING.md)

![真实国服海图：库存、已求解的九宫格布局、区域目标与策略](docs/images/planner-real-layout.png)

*使用[九张真实国服海图](src/logic/__fixtures__/real-inventory-layout.json)重新求解的可执行布局；截图展示库存、十二条边界和区域目标。*

## 功能

保留原版的 3×3 规划板、十二条边界、海图旋转与位置锁定、候选求解、效果统计及分享能力。

| 国服适配与新增功能 | 用途 |
| --- | --- |
| **国服高级复制导入** | 从游戏以 `Ctrl+Alt+C` 复制海图，粘贴解析名称、区域等级、目的地、连接形状和词缀；五种形状已有真实客户端样本。无法可靠识别的内容会给出反馈。 |
| **Windows 被动采集器** | 在导入说明下载，F7 保留计数浮窗并汇总手动高级复制的海图，按住 Alt 后 F8 在本机识别十二条边界；采集错误在浮窗提示，再一次粘贴导入。 |
| **集中式策略选择** | 七种策略和手动模式集中在右侧；玩法、材料缺项、布局、中心偏好及攻略随选择更新。特殊材料触发的推荐会说明原因和缺项，由玩家主动切换。 |
| **区域目标提示** | 在九宫格中央显示本格应关注的目标，结合目的地及实际生效的词缀，按策略排序。同类合并，最多四槽，支持「关闭／高价值／全部」及展开详情。 |
| **当前边界价值** | 按当前策略给每条边界分为灰色「可略」、蓝色「留意」、金色「优先」。分析弹窗按权重降序展示十二条边界的理由、来源和规则版本。 |
| **独立留图助手** | 不用先导入库存，即可按策略查看留图条件；有专项规则时可复制一条完整正则，在游戏中手动寻找和整理海图。 |
| **清楚的策略预留** | 库存标记展示哪些海图为策略材料预留；策略预留与摆盘位置锁定分别管理。网页不会替你锁定或移动游戏内的物品。 |
| **航程核销与历史参考** | 实际完成航程后确认存活海图、核销消耗，记录航程。用最近同策略、同计分口径的个人历史比较当前摆盘；样本不足时明确提示。 |
| **中文校准** | 默认隐藏维护入口，打开铅笔模式后可直达单条词库记录，查看英文、中文与来源对照。建议和备注保存后可预览并选择本次提交的记录与完整 JSON；较短内容自动预填 GitHub Issue 草稿，较长内容可复制完整正文后粘贴，最后在 GitHub 核对并发布。 |
| **本地保存与完整备份** | 库存、摆盘、边界、策略配置与历史在浏览器保存，支持 JSON 备份和恢复；另保留旧校准记录备份的导入与损坏数据恢复。支持简洁的明暗主题。 |

## 快速开始

需要 **Node.js 20+** 和 npm。

```sh
git clone https://github.com/ren2019/allflame-voyage-cn.git
cd allflame-voyage-cn
npm ci
npm run dev
```

打开终端显示的本机地址，通常为 `http://localhost:5173`。构建静态站点：

```sh
npm run build
```

生成目录为 `dist/`，可自行部署到静态服务器。多台电脑经局域网使用时，按 [HTTPS 部署说明](docs/local-deployment.md) 配置证书，让一键复制可用。

GitHub Pages 的目标地址为 `https://ren2019.github.io/allflame-voyage-cn/`。仓库 Settings → Pages 的发布源选择 GitHub Actions 后，现有工作流会将 `dist/` 直接发布到项目站首页；可手动触发，也会在推送 `main` 时运行。启用状态、费用与限制见 [Pages 部署研究](docs/research/github-pages-deployment.md)。

## 一次航程的用法

1. 在游戏中高级复制海图，粘贴到导入框，核对库存；填写外圈十二条边界。
2. 在右侧选择策略，查看材料和摆法要求，按需设置预留、布局及中心海图。
3. 点击求解，检查并应用可执行候选。区域目标帮助跑图，边界分析解释当前策略看重哪些边。
4. 使用复制指南，在游戏中手动搜索海图、摆放和调整朝向。
5. 实际跑完后点击「完成航程」，确认存活与消耗，更新库存和历史，再规划下一轮。

## Windows 海图与边界采集

更新、修复和卸载的候选实现与证据边界见[维护验收说明](docs/acceptance/collector-maintenance-75.md)。旧 0.2.2／0.2.3 从新候选包内的中文安装入口升级；成功安装维护版后才出现桌面“国服海图采集器维护”。真实 Windows 版本切换、授权和游戏操作仍待玩家验收。

1. 本轮提供待验收的[完整安装候选流程](public/collector/installer/使用说明.html)：解压候选包，双击“安装或更新国服海图采集器.cmd”，完成组件及模型检查后从桌面“国服海图采集器”启动并确认正常 Windows 管理员授权。尚未公开发布安装包；候选构建与实际验收边界见[安装验证说明](docs/acceptance/collector-install-73.md)。裸 `voyage-clip-collector-cn.ahk` 为高级维护入口，需要同版本固定组件，单独安装 AHK 不足以准备中文 OCR。页面、浮窗、托盘与[版本清单](public/collector-release.json)应一致。
2. 按 F7 开启采集，放大的中文计数浮窗显示数量、状态和采集错误。逐张悬停已测绘海图，手动 Ctrl+C 复制；需要完整高级属性时使用 Ctrl+Alt+C。
3. 需要边界时，自己按住 Alt 显示十二条提示，再按 F8。听到截图完成提示音或看到浮窗提示后松开 Alt，等待本机 OCR；图片不会上传。
4. 再按 F7 结束，到网页 Ctrl+V 一次导入。只更新边界可不启用 F7，单独按住 Alt 后按 F8，完成后直接粘贴。Shift+F7 可静音，浮窗仍显示。

缺少简体中文 OCR 组件时，浮窗会提示安装方法；在 Windows 设置的简体中文语言选项中安装光学字符识别后重试，也可继续手动选择边界。浮窗读取数量表示得到文字，最终词缀匹配数量和失败位置以网页为准；未匹配的位置点击外圈槽位补选。连续相同海图文本只采集一次，网页继续按原文和库存数量去重。

采集器沿用原版按窗口尺寸缩放的定位方式，不增加分辨率配置。2026-10-28，用户已在 Windows 使用 Ctrl+C 完成海图采集并导入原生产网页，随后要求将本波全部更新统一发布。放大后的浮窗、截图 OCR 与十二槽位置继续按[现场清单](docs/acceptance/field-checklist.md#国服采集器54)在生产核对；海图导入通过和发布授权不代表边界 OCR 已通过。旧自动批量操作脚本保持停用，采集器不会替玩家操作游戏。

## 数据与适用范围

- **无需账号或后端。** 规划和校准记录保存在当前浏览器、当前站点地址的本地存储。更换浏览器、协议、IP 或端口前，请导出规划备份并保留校准预览中的 JSON；分享摆盘与完整规划备份的用途不同。校准反馈需在 GitHub 登录并最终发布。
- **策略与提示需要结合游戏版本。** 目标、边界和留图规则由版本化配置驱动。译名参考真实国服复制样本及 [PoEDB](https://poedb.tw/cn/)，尚未逐条在目标客户端确认的资料保留来源和缺口。
- **分数是规划参考。** 摆盘评分、边界权重、目标展示优先级和个人历史位置衡量的对象不同，均不表示收益保证或通用的策略起跑门槛。
- 中文校准保存的是建议；不会直接覆盖正式译文、解析规则或评分。详见 [校准说明](docs/calibration.md)。
