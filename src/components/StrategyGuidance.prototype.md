# 策略行动提示：临时 UI 原型

问题：保留现有九宫格和评分，怎样让玩家第一眼认出关键区域及条件先后关系？

当前结论：待用户选型；作者建议 A。没有将任何方案视为用户已认可，也没有集成到正式界面。

## 启动与对比

运行 `npm run prototype:strategy`，打开 `http://127.0.0.1:4191/?prototype=strategy&variant=A`。

- A：卡片常驻目的地／位置与动作，顶部一句打法。
- B：九宫格旁的动作清单，点击动作组高亮对应区域。
- C：顶部阶段切换，聚焦该阶段的目标；不写入游戏进度。

底部箭头或键盘左右键切换；URL 中 `variant=A|B|C` 可直接分享并在刷新后保留方案。右侧可切换八个策略或手动模式。刷新会重置演示摆盘。

## 范围

同一路径的 `prototype=strategy` 参数仅在开发模式生效，生产构建不包含原型。真实 `Board.tsx` 和 `App.tsx` 没有改动；`StrategyBoard.prototype.tsx` 是为快速对比复制的临时渲染。沿用实际库存、策略说明、目标投影、评分和主题组件；不复用用户库存。

演示海图是人工构造的 UI 场景，不是求解结果，不证明八个策略的材料完整或游戏机制已校准。演示状态仅在内存；库存只读，卡片可交换／旋转，边界可临时修改。原型不会调用求解器、写入库存、核销或向游戏复制。点击“无策略”展示通用探索提示。

锚地的赐福位置及玩家是否已取得目标赐福均未知。锚地在起点时也只能提示可经过、暂不开宝藏。保险箱和灯笼标记从实际生效区域投影取得，不把供给海图视为实际目标。同组区域不是固定的走图顺序。

## 已做的检查

- TypeScript 与生产构建通过；生产资源中未包含原型切换器及原型页面。
- 浏览器实际打开 A/B/C，切换八策略、箭头循环、刷新保留方案、交换锚地到起点、阶段聚焦及明暗主题。
- 390px 窄屏下检查锚地／稀有怪传说装／速刷保险箱的三个方案，没有页面横向溢出。
- 上述浏览器演示无脚本错误、localStorage 为空。不新建测试套件；本原型只用于设计评审。
