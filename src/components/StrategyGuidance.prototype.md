# 策略行动提示：编号 overlay 原型

问题：保留现有九宫格与评分，直接在区域目标 overlay 中用 1、2、3、4 点出少数优先行动并体现顺序。

## 已确定的方向

用户否定了初版 A 卡片动作签、B 打法清单、C 阶段聚焦，明确要求直接使用类似区域目标的 overlay、数字体现顺序，并不需要给九格全部编号。初版主要来源保留在本分支提交 `1d30cdd`。本次仅迭代这一方向，没有把新版视觉或具体推荐算法视为已获用户认可。

## 启动

运行 `npm run prototype:strategy`，打开 `http://127.0.0.1:4191/?prototype=strategy&variant=numbered`。此前 A/B/C URL 也会显示本次新版。右侧切换策略，点击两格交换位置，“打法顺序”勾选框切换数字 overlay。

## 本次展示规则

- 数字与已有区域目标图标放在同一个中央 overlay，最多四个行动；其余格保持原有内容。
- 数字不取自区域评分，不代表复制到游戏的放置次序。
- 锚地示例先标最多三个探索候选，最后标锚地并常驻“赐福后开”。探索候选按起点及上个候选的连通距离选取，不声称这些格确定存在赐福，也不表示探索三格后即可无条件开宝藏。
- 琪莎拉只标实际 Boss 格；保险箱仅标实际收到目标的区域；稀有怪／魔法怪流先列少量灯笼动作，再列怪物目标。
- 同一格需要先收灯笼、之后处理怪物时，可有两个行动编号；这是操作次序，不是要求只进该格一次。
- 没有已识别的专项目标就不凑编号。手动模式与本次普通点金演示可以没有编号。
- 连通距离、候选数量和同优先级处理均为临时演示规则；正式推荐算法仍待讨论。

## 隔离与验证

这是开发模式原型，生产构建不包含原型。`Board.tsx` 与 `App.tsx` 没有修改；仅使用内存中的人工演示海图，不读取或写入用户库存，不运行求解器或核销，不自动控制游戏。刷新恢复演示初始状态。

本次已检查构建、八策略与手动模式、最多四个编号、锚地移至起点、提示关闭后恢复、390px 窄屏无页面横向溢出、无浏览器脚本错误、localStorage 为空。已检查交换位置、锚地起点场景与浅深主题。演示使用四向连接海图，以便交换后仍可比较编号。没有为临时原型新增测试套件。
